# 接点戦略: 好みの入口から使えるようにする（2026-10）

作成日: 2026-10-21
ステータス: 方針確定（実装は未着手）

訪日客・宿泊施設・自治体が、それぞれ好みの接点（QR・サイト埋め込み・サイネージ・メッセージアプリ・ストアアプリ）から使えるようにするための方針と順番。
差別化の全体像は [差別化戦略](../strategy/differentiation-and-social-impact.md)（軸A「インストール不要」）を前提とし、本書はその**接点の作り方と順番**を決める。

---

## 1. 前提と制約

- **無料ポートフォリオとして公開する**（2026-09-23 裁定。[引き継ぎ](handoff/2026-09-23_cloud-run-portfolio-release.md)）。B2B の本格展開はしない
- 費用上限は構造で固定する: Cloud Run `--min-instances 0 --max-instances 1`
- PUBLIC + MIT。売れるのはコードではなく運用・責任なので、接点を増やすほど「責任の範囲」を明示する必要がある

## 2. 現状（2026-10-21 コード確認）

| 項目 | 現状 | 出典 |
|---|---|---|
| iframe 埋め込み | 禁止（`frame-ancestors 'none'` + `X-Frame-Options: DENY`） | `frontend/src/middleware.ts:49,61` / `backend/app/main.py:191-198` |
| URL での言語・地域指定 | 不可（`searchParams` 使用 0 件。言語はブラウザ言語から自動判定） | `frontend/src/i18n/detectLanguage.ts` |
| ページ構成 | 単一ページ | `frontend/src/app/page.tsx` |
| PWA | 対応済み（`display: standalone`） | `frontend/public/manifest.json` |
| 外部からの API 利用 | CORS 許可リスト制 | `backend/app/main.py:164-175` |
| 市町村の避難指示・避難所開設 | **扱っていない**（データ源は気象庁・国土地理院のみ） | — |

## 3. 決めたこと

### 3.1 原則: 1 つの中身 × URL で切り替える薄いビュー

接点ごとに画面を作らない。表示モード・言語・地域を URL で指定し、同じ中身を出し分ける。16 言語 × 接点数で保守量が掛け算になるのを防ぐ。

### 3.2 主役は「入れなくても開ける」接点

訪日客は旅行前に防災アプリを入れない。困ったその場で開ける QR・リンクを主役にし、ストアアプリ（TWA）は実績の看板として後に回す。

### 3.3 順番

| # | 内容 | 担当 | 公開 URL が必要か |
|---|---|---|---|
| 0 | 公開 URL を作る（Cloud Run。[手順](../ops/deployment.md) 第 6 節） | **オーナー**（`gcloud run deploy` は Claude 実行不可） | — |
| 1 | URL で言語・地域を指定（`?lang=&pref=`）+ OGP 整備 + **宿向け QR ポスター PDF の自動生成** | Claude | 実装は不要。ポスターの最終出力のみ必要（ベース URL を引数にする） |
| 2 | **静的スナップショット**: 表示用 JSON を 1 分ごとに生成し、CDN / オブジェクトストレージから配る。最終更新時刻を常時表示。同じ JSON を公開フィード（JSON / CAP）としても出す | Claude（配置先バケットの作成はオーナー確認） | 実装は不要。配信開始時に必要 |
| 3 | `/signage` ビュー（ロビー・館内テレビ向け。大きな文字・言語の自動ローテーション） | Claude | 実装は不要 |
| 4 | `/embed`・LINE ボット・TWA は 1〜3 の反応を見て判断 | — | — |

**1〜3 は公開 URL を待たずに実装できる。** 公開 URL を待つのは、ポスターの最終出力・フィード配信開始・疎通確認だけ。

### 3.4 常時表示する範囲の明示（どの接点でも）

- 「気象庁情報の中継であり公式発表ではない」と出典
- **避難指示・避難所開設はこのアプリでは扱っていない**旨と、各市町村の公式ページへの導線

## 4. 後回し・見送りにしたこと

| 案 | 判断 | 理由 |
|---|---|---|
| `/embed`（他サイトへの iframe 埋め込み）を先行 | 後回し | 他サイトに埋め込まれると、偽装された画面で操作を誘導される危険（クリックジャッキング）や公式との誤認を招く。避難指示が欠けているのに使えるように見え、免責表示では消えない。先に開くなら「リンク／バナー＋フィードを渡し、表示責任は相手側」の形 |
| 自治体を最初の利用者にする | 後回し | 自治体にとって最重要の避難指示が欠けている。宿泊施設（災害時に役立った情報源 1 位 30.3%、[需要調査](../research/inbound-disaster-needs-2026.md)）を先にする |
| Safety tips との正面対抗 | 見送り | 観光庁監修・15 言語・プッシュ・Lアラート経由の避難情報・**他システム向け API あり**。[差別化戦略](../strategy/differentiation-and-social-impact.md) §1 の「ネイティブアプリ必須」は事実だが、データ提供の面では先行されている |
| 動的 API・SSE を外部接点から直接叩かせる | 不採用 | max-instances=1 では、災害時に最も必要な瞬間に落ちる |

## 5. 検証の経緯

2026-10-21、Claude の戦略案を Gemini・GPT で並列検証した（`/AI-2G`）。

- **3 者一致**: インストール不要の接点を主役にする / 静的スナップショットは必須 / 避難指示の欠落は自治体向けに致命的
- **分岐**: 埋め込みの優先度（Gemini=最優先、GPT=後回し）→ GPT 案を採用（§4）
- **取り込んだ追加案**: データ提供特化（Gemini → 順番 2 の公開フィードとして吸収）、空港・駅の無料 Wi-Fi 接続後ページ（Gemini）、NFC タグ・客室タブレット（GPT）→ 順番 1 の QR / URL がそのまま使えるため、個別実装はしない
