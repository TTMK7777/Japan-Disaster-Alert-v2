### ギャップ

1. ~~**`WARNING_GUIDANCE` が 2 言語しかない。**~~ → **2026-07-30 対応済み。** `backend/app/services/warning_guidance.py` を新設し、**災害種別13グループ × 16言語**の行動指示を用意した。特別警報には「命に関わる危険」の接頭語を付ける。ja / en のコード別文面は従来どおり優先されるため既存挙動は劣化しない。
   - **前回の記述の訂正**: 実行時は `guidance.get(lang, guidance.get("en", ""))` で**既に英語へフォールバックしていた**。したがって本件は「日本語が出ていた」のではなく「**14言語が英語だった**」が正確。深刻度は当初の記述より低い。
   - **設計上のトレードオフ（意図的）**: 29コード × 16言語 = 464 文面を無レビューで量産するリスクを避け、13グループ × 16 = 208 に抑えて一つ一つ丁寧に書いた。災害種別の細かいニュアンス（例「除雪時の事故」）は落ちる。コード別に増やしたくなったら `WARNING_GUIDANCE` に言語キーを足せばグループより優先される。
   - 併せて軽微な齟齬: README / CHANGELOG は「28 種類」と記載しているが、辞書の実測は **29 種**。

   **警報名も 2026-07-30 に16言語化した** → `backend/app/services/warning_names.py`。29コード × 16言語を並べる代わりに「**災害種別18語 × 警報レベル3語 + 言語ごとの語順**」の合成方式にした（語順の例: ja「大雨警報」/ vi「Cảnh báo mưa lớn」/ fr「Alerte : fortes pluies」）。
   - **既存6言語の文面は1文字も変えていない**。移行前の29コード分の文面をテストに凍結し、合成結果と全件突合している（`TestNoRegression`）
   - 説明文テンプレも16言語化済み

   **地域名も 2026-08-01 に対応した** → `backend/app/services/area_display.py` + 生成物 `area_names.py`。

   当初は「`AREA_TRANSLATIONS` が 4地域×5言語しか無い」という問題だと見ていたが、実データを取って調べたところ**前提そのものが誤り**だった。気象庁の警報 JSON に地域名は入っておらず `code` しか無い（東京 130000 / 沖縄 471000 の実レスポンスで確認）。実装は `area.get("name", "") or prefecture_name` と書いていたため、**`AREA_TRANSLATIONS` は一度も引かれていない死蔵コード**で（キーが「東京地方」なのに実際に渡るのは「東京都」）、全16言語で都道府県名（日本語）が出ていた。

   気象庁公式の地域マスタ（`/bosai/common/const/area.json`、全階層に `enName` を持つ）から **193地域ぶんの日本語名・英語名を生成**し、コードから解決するようにした。副次的に表示の粒度が上がっている（「東京都」→「伊豆諸島北部」）。

   - **言語の方針**: `ja` / `easy_ja` は日本語名、他14言語は公式 `enName`。**193地域 × 14言語 = 2,702 件の固有名詞を無レビューで量産しない**という判断（警報名を合成方式にしたのと同じ理由）。英語名は駅名・道路標識・避難所看板のローマ字表記と一致するため、現地で照合できる実利がある。レビュー済みの訳は `AREA_NAME_OVERRIDES` に置けば公式名より優先される
   - 既存の手訳4件のうち3件が公式 `enName` と完全一致しており（Northern Izu Islands / Southern Izu Islands / Ogasawara Islands）、マスタの妥当性の裏付けになった

   **この調査中に、地域名より重い不具合が3件見つかった**（いずれも同じ PR で修正済み）:

   | 不具合 | 影響 | 原因 |
   |--------|------|------|
   | 継続中の警報が全部消える | **最重要**。実測で沖縄は継続62件・解除29件・発表0件だったが表示ゼロ | `status == "発表"` だけを通していた。気象庁は2回目以降の更新で「継続」に変える |
   | 鹿児島県の警報が永久にゼロ件 | 県まるごと機能不全。エラーも出ない | `460000` は存在しないコード（404 → 例外 → `[]`）。実際は `460100` と `460040` の2予報区 |
   | 10言語が16言語対応の恩恵を受けていない | th/id/ms/tl/fr/de/it/es/ne/zh-TW で警報名が英語固定・地名が空文字 | `STATIC_LANGUAGES` が6言語しか無く、残りは AI 経路へ。AI 経路には都道府県フォールバックすら無かった |

   3つ目は**既存テストが本番の通らない経路を検証していた**ために見逃されていた（テストは `_parse_warnings` を直接呼び、本番の入口 `get_warnings` の言語分岐を通っていなかった）。再発防止として、入口を通すテストを追加している。

   **予報区の取りこぼしも同日に解消した**（PR#68）。府県予報区は 58 件あり「1都道府県=1予報区」ではない（北海道8・沖縄4・鹿児島2）が、各県の代表コード1つしか見ていなかったため、**北海道は石狩・空知・後志のみ、沖縄は本島のみ**で、宮古島・八重山・大東島・奄美と北海道の7予報区の警報が利用者に一切表示されていなかった。全国の特別警報スキャン（＝Push通知の元）も同じ取りこぼしをしていた。都道府県を指定すると全予報区を並列取得して統合する。利用者から見える地域選択は 47 都道府県のまま変えていない（「シンプルに使える」方針を崩さないため）。実測で北海道は表示される警報が2種→5種に増えた。
2. **`IntensityGauge` の `descriptions` はソース上のコメントが「直感的な行動指示」だが、実体は現象の描写。** 「震度6強 = 這わないと動けない」は状況説明であって、訪日客が知りたい「だから今どうすべきか」ではない。
3. ~~**`safety_guide._get_fallback()` が日本語ハードコード。**~~ → **2026-07-30 対応済み。** `backend/app/services/safety_guide_fallback.py` を新設し、**16言語**の静的フォールバックに差し替えた。未対応言語は日本語ではなく **`en`** に落とす（読めない人に読めないものを返さないため）。レスポンスに `fallback` フラグを追加し、静的ガイドか AI 生成かをクライアントが判別できるようにした。
   - モジュールは**外部依存ゼロ**なので、停電・低回線・APIキー未設定のいずれでも動く（R2 とも両立）
   - 回帰テスト 218 件追加（backend 86 → **304 件**）。旧実装に戻すと12件 fail することを確認済み

## R2. 停電・低電力・低回線で動く

### 現状

`frontend/public/sw.js` の実測:

| 対象 | 戦略 | 場所 |
|------|------|------|
| 静的アセット | cacheFirst | `sw.js:84-85` |
| `/api/**` | **networkFirst（キャッシュへフォールバック）** | `sw.js:86-87` |
| 地図タイル（GSI / OSM） | cacheFirst + 7日有効 | `sw.js:88-89` |
| プリキャッシュ対象 | `/`, `manifest.json`, `offline.html`, アイコン2枚 | `sw.js:9-15` |

→ **一度でも開いていれば、オフラインでも直近の災害情報と地図タイルが読める。** これは R2 の中核が満たされている。

### ギャップ

1. ~~**プリキャッシュに避難行動の静的コンテンツが含まれていない。**~~ → **2026-07-30 対応済み。** `public/offline.html` を「オフラインです + 緊急連絡先（5言語）」から、**3ステップの行動指示を含む16言語の行動ガイド**に拡張した（身の安全確保 → 火を消し高い場所へ → 公式指示に従う）。ブラウザ言語から自動選択し、外部リソースを一切読まない。`offline.html` / `offline.js` は SW のプリキャッシュ対象。
   - **前回の記述の訂正**: 「初回訪問がオフラインだと何も出せない」と書いたが、`offline.html` は元から `STATIC_ASSETS` に入っており SW が HTML リクエスト失敗時に返していた（`sw.js:146-149`）。正確には「**プリキャッシュされる内容に行動指示が無かった**」。なお **Service Worker 自体が1度目の成功ロードで初めて登録される**ため、「本当の初回訪問がオフライン」のケースは Web アプリの構造上どうしても救えない（ホテル等で一度開いてもらう前提になる）。
   - **実装中に CSP の落とし穴を踏んだ**: 最初はインラインスクリプトで書いたが、`middleware.ts` の CSP（`script-src 'self' 'nonce-...'`）に阻まれて**言語切替が一切動かず、行動指示が空欄で表示された**。しかも SW はレスポンスヘッダごとキャッシュするため、オフライン時も同じくブロックされる。同一オリジンの外部スクリプト `offline.js` に切り出して解決。`onclick` 属性も同じ理由で使えない。再発防止テストあり。
2. **省電力設計が無い。** `prefers-reduced-motion` の対応のみ（`frontend/src/app/globals.css:188`, `frontend/public/offline.html:134`）。バッテリー残量に応じた低電力モード（地図・SSE・ポーリング停止、白背景を暗色へ）は未実装。停電で充電できない 67% に対して、**アプリ自体が電池を食う側**になっている可能性がある（実測はしていない = 未検証）。
3. **SSE 常時接続が電力・通信を消費し続ける。** `/api/v1/events/stream` は 10 秒ポーリング + 30 秒ハートビート。低電力時に切る導線が無い。

### 対応の方向

- ~~「オフライン最小行動ガイド」を全言語ぶん静的生成しプリキャッシュ~~（2026-07-30 完了）
- Battery Status API（対応端末のみ）または手動トグルで低電力モード
- 低電力モードでは SSE を切り、ポーリング間隔を延ばす

### ギャップ

1. **OG メタが日本語主体。** SNS でシェアされた瞬間に外国人へ提示されるカードが日本語で、想定ユーザーに刺さらない。16 言語対応を謳いながら、SNS 上の第一印象は日本語。
2. **共有機能が無い。** `navigator.share` / シェアボタンの実装なし。役立った情報源に「日本にいる外国人の SNS 書き込み」23.8% が入っているのに、**ユーザーが他の旅行者へ拡散する導線が無い**。
3. **デマへの反証コンテンツが無い。** 2025 年の「7月5日」デマで香港が 33% 減という実害があり、気象庁は「日時を特定した予測は科学的に不可能」と明言している。この種の**公式見解を多言語で即座に提示する枠**が無い。JNTO の SNS が 2 言語しかない空白は、ここで埋められる。

### 対応の方向

- OG メタを英語基調にし、言語別 OG（動的 `generateMetadata`）へ
- 「この情報は気象庁の公式発表に基づく」ことを明示する出典表示 + シェア導線
- デマ検証セクション（公式見解の多言語提示）
